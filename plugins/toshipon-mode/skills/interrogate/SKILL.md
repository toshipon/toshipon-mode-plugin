# Interrogate

敵対者が変更や設計を壊しにかかる。所見が残るのは、実行で証明されたときだけである。所見を報告する。修正は適用しない。

## Frame

スコープはユーザーが名指ししたものにする。名指しがなければ、ベースブランチとの merge base からのブランチの diff に、作業ツリーの変更を加えたものにする。ユーザーのメッセージ、コミット、PR の説明から、`/toshipon-mode:in-your-own-words` の要領で意図を言い直す。意図がはっきりしないときはユーザーに聞く。

## Fan out

**arena** skill の Phase A の手順 3 と 4、そして Phase B を、次の 4 点を変えて実行する。

- 敵対者は `opus`、`sonnet`、`haiku` に 1 体ずつ置く。model は変えず、`effort` だけを toshipon-mode skill の Delegation 節に従って選ぶ。
- スコープの未 commit の変更を、各 worktree にコピーする。
- 各敵対者は `subagent_type: "general-purpose"` で起動する。
- arena のタスクと根拠の代わりに、スコープ、意図、次の brief を渡す。

> この変更を壊せ。各所見を、実コードに対する実行で証明する。たとえば失敗するテスト、再現スクリプト、誤った挙動を示すコマンド出力である。設計やプランなら、prototype を走らせるか、現在のツリーを調べる。再現は自分の worktree の中に置く。各所見は、タイトル、正確なコマンド、それが出力したもの、意図が求める出力を添えて報告する。実行しなかったものは書かない。スタイル、命名、構造、将来の変更があって初めて問題になるリスクも書かない。所見なしも有効な結果である。

## Verify

arena の Phase F の要領で、各所見のコマンドを再実行して確かめる。出力が失敗を示し、その失敗が意図を壊すときだけ所見を残し、残りは落とす。根本原因が同じ所見はまとめる。

arena の Phase C、D、E は飛ばす。敵対者はそれぞれ違う失敗を見つけるので、判定には 1 体の敵対者のリストではなく、確かめたすべての所見を残す。

## Output

- **Intent.** 言い直した意図。
- **Findings.** 確かめた所見ごとに、コマンド、その出力、それが意図をどう壊すか、見つけた敵対者。残った所見がなければ「確かめた所見なし」と書く。
- **Dropped.** 敵対者ごとに、落とした所見の数と理由。
