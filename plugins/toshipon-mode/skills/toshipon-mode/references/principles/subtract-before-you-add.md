# Subtract Before You Add

システムを進化させる時は、まず複雑さを取り除き、その上で構築する。デフォルトを subtraction にする。

シンプル化を継続的な投資として扱う。同じか、それより小さい surface の裏側で、見つけた時よりも設計をわずかにシンプルで、より高機能な状態にして残す。

- 構築より先に削除を順序付ける
- 磨き上げる前に削ぎ落とす（品質へ投資する前に最小限にたどり着く）
- 想定される speculative なエッジケースではなく、観測された実際の使われ方に合わせて設計する
- 仕様が求める以上の speculative な validator・parser・guard を作らない
- 仕様外の機能は validator を後ろに引きずる。永続化、起動時の retry、スキーマ migration はそれぞれ、自分の入力を守るための guard を必要とする
- プロンプトをシンプルにする（冗長な指示、過剰なテンプレートを取り除く）
- 参照先に novel な内容がなければ、stub として残すのではなく削除する
