# Explain the Number

- **実行する前に判断を書く。** 判断を変える結果と、ノイズの下限を名指しする。実行ごとのばらつきが効果より大きいなら、そこで止める。
- **「なぜ 2 倍ではないのか」を問う。** 結果を頭打ちにしている resource か code path を、実行中に取った profile かシステムカウンタから名指しする。コードを読んで推測したものは limiter ではない。
- **その数値が他に何を測っている可能性があるかを列挙し**（エラー、スキップやキャッシュで省かれた作業、実行されなかったコード、チューニングされていない側、ノイズ、効くには小さすぎる部分）、それぞれを証拠で潰す。
- **実行回数、ばらつき、limiter を数値と一緒に残す。**

性能の数値なら [benchmark-checklist](../benchmark-checklist.md) を通す。eval の結果なら、すべての実行がタスクをこなしたか、差が試行とモデルをまたいで保たれるか、そのシナリオに意味があるかを問う。
