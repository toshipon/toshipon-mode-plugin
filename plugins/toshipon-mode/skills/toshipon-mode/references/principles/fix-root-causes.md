# Fix Root Causes

デバッグ時は症状を覆い隠さない。すべての問題を根本原因まで遡り、そこで修正する。

**理由:** 症状への対処は積み重なる。ワークアラウンドを重ねるたびにシステムは推論しづらくなり、しかも本当のバグは残ったままになる。根本原因の修正は最初は時間がかかるが、デバッグの総時間を減らす。

**パターン:**
- まず再現させる（再現できなければ、修正を検証できない）
- 根本原因に行き着くまで「なぜ」を問い続ける
- ガードを足したくなる衝動に抗う（クラッシュを黙らせるための nil チェックは症状への対処にすぎない）
- ワークアラウンドを正当化するのに段落レベルのコメントが要るなら、コードが間違っている（コメントではなくコードを直す）
- 個別の事例だけでなくパターンを確認する（同じパターンを grep し、すべての事例を修正する）
- 行き詰まったら計測する。推測しない（ログを足し、実際のエラーを読む）

**再起動時のバグ: コードよりまず state を疑う**

実行間でコードは変わらない。変わるのは state である。「再起動後に失敗する」場合は、まず古くなった永続的な state（config ファイル、キャッシュ、ロックファイル、シリアライズされた state）を疑う。state ファイルをクリアすることで動作が元に戻るなら、state バリデーションを修正として優先する。
