# Guard the Context Window

コンテキストウィンドウは有限であり、セッション内では再生されない。入ってくるすべてのトークンは、そこに入る価値を持つべきである。

**理由:** コンテキストのオーバーフローは推論品質を下げ、圧縮によるアーティファクトを生み、進捗を止める。compute や時間と違い、セッション内で消費したコンテキストは取り戻せない。

**パターン:**
- **大きなペイロードは隔離する。** 冗長な出力、スクリーンショット、大きなドキュメントは subagent に逃がす。メインの context には要約だけを残し、生データは渡さない。
- **頻繁に使う内容はインラインに保つ。** 呼び出すたびに使うテンプレートや参照情報は、都度読み込みコストのかかる別ファイルではなく、skill や rule ファイル自体に含める。
- **フェーズの規模を決め、スコープに上限を設ける。** フェーズごとのファイル数を制限し、ターン予算を設定し、mechanism 自体のコストも見込んでおく。
