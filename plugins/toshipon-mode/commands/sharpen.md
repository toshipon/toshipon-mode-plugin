# /toshipon-mode:sharpen

着手する前に、次を問う。一流の専門家ならこのタスクにどう取り組むか（どの一次情報にあたり、実際にどんな方法を使い、結果が正しいことを外からどう確かめるか）。ユーザーが本当に求めているものは何か。タスクの指定は過剰か、不足か。

目的に役立たない制約は、役立つ制約を足すのと同じくらい気軽に緩める。ユーザーが決めるべき選択は、自分で決めずに開けておく。取り込むのは作業を良くするものだけで、作業を大きくするものは取り込まない。ただし、結果が正しいことを外から確かめるチェックは必ず 1 つ残す。

この見立てを語らずに、そのまま作業する。書き直したプロンプトを返さない。
