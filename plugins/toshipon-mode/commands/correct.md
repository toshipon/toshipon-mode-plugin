# /toshipon-mode:correct

ユーザーはこのリポジトリで、agent の同じミスを何度も訂正している。次の agent がそのミスをできないように、リポジトリの方を変える。

すべての contributor は agent だと仮定する。開いたファイルしか見ず、いちばん近い例を真似し、コンパイルが通る最短の道を選ぶ。1 ファイルから見て正しく見える変更が、リポジトリ全体にとっても正しくなるように設計する。

考え方は encode-lessons-in-structure 原則（`${CLAUDE_PLUGIN_ROOT}/skills/toshipon-mode/references/principles/encode-lessons-in-structure.md`）と同じで、このコマンドはそれをリポジトリ全体に対して一度に回す手順である。

## ミスのクラスを見つける

まず、最近のコミット、revert、レビューコメント、agent 向けの指示ファイル（`CLAUDE.md`、`AGENTS.md`）、workaround を説明しているコメントを読む。ミスをクラスにまとめる。2 回起きたら 1 つのクラスとして数える。

## 各クラスを、効く中でいちばん高いレベルで直す

1. **architecture で消す。** state ごとに owner を 1 つ、タスクごとにサポートされたやり方を 1 つにする。内部を隠し、間違った import が失敗するようにする。手で同期しているリストは single source of truth に置き換える。agent が真似しそうな古いやり方と dead code は削除する。
2. **types で強制し、悪い状態を書けなくする。** それでも悪いコードがコンパイルを通るなら、lint か CI チェックを足す。そのエラーは、代わりに使うべきファイル・型・関数を名指しする。そのパターンがすでに広く使われているなら、変更がそれを増やしたときだけ落とす。
3. **振る舞いをテストする。** 2 つの編集を想像する。チェック対象の振る舞いを壊す編集と、内部だけを変える編集である。前者で落ちないテスト、後者で落ちるテストは、直すか削除する。
4. **docs や agent 向けルールは最後に、判断が要るものだけに書く。** agent がそれを読み飛ばしても、何も落ちないからである。

## 直して証明する

頻度の高いクラスから、1 クラス 1 コミットで今すぐ直す。新しいチェックが、過去の実際のミスで落ちることを証明する。ローカルと CI で同じコマンドを走らせる。例外は違反している行そのものに、理由・期限・人間の承認を添えて置く。

## ルール表を保つ

最後に、agent 向けの指示ファイルに、各ルールとそれを強制しているものを対にした表を置く。置き場所はリポジトリの `CLAUDE.md`、無ければ `AGENTS.md` である。ユーザーに訂正されたら、ミスを直してルールを足す。ルールがすでに表にあり、それを強制するものが何もないなら、それは再発である。同じ変更の中で、いちばん高いレベルで直す。ミスが起こり得なくなったルールは表から外す。

**返信:** クラスごとに、その証拠、選んだレベル、それより高いレベルが効かなかった理由を書く。
